# Fase 2 — Emisión de tokens sobre Spring Authorization Server · Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sustituir la emisión de tokens de la fase 1 por *Authorization Code* + PKCE con un cliente OAuth por aplicación, conservando intacto el modelo RBAC.

**Architecture:** Spring Authorization Server (parte de Spring Security 7) emite; `auth_app` sigue siendo el único registro de clientes mediante un `RegisteredClientRepository` propio; Google es el proveedor de identidad federado que establece una sesión SSO en `auth`; y un `OAuth2TokenCustomizer` enchufa `AccessGrant` para poner `roles` y `permissions` en el token.

**Tech Stack:** Java 25 · Spring Boot 4.1.1 · Spring Security 7.1.1 · `spring-security-oauth2-authorization-server:7.1.1` · Spring Session JDBC · Gradle 9.6.1 · Flyway · Testcontainers · MySQL 8.4 y PostgreSQL 17

**Spec:** `docs/superpowers/specs/2026-09-18-oauth-authorization-server-design.md`

**Branch:** crear `feat/oauth-authorization-server` desde `develop`

## Lo que la prueba de concepto ya descubrió — no volver a descubrirlo

Se ejecutó el flujo completo contra 7.1.1 antes de escribir este plan. Cinco cosas que cuestan una tarde cada una si se aprenden sobre la marcha:

1. **Los paquetes se movieron.** El DSL está en `org.springframework.security.config.annotation.web.configurers.oauth2.server.authorization`, **no** en `…oauth2.server.authorization.config.annotation.web.configurers`. Todo el material publicado usa el segundo, porque está escrito contra el proyecto archivado. **No copiar imports de tutoriales.**
2. **La autoconfiguración no da un login.** Sin dos cadenas declaradas a mano, `/oauth2/authorize` devuelve **401 con `WWW-Authenticate: Bearer`**. La cadena del authorization server **no autentica**: depende de la sesión que establezca la otra.
3. **El validador debe pasar `ctx.getAuthentication()` a su excepción.** Con `null` el usuario recibe un **400 crudo**; con el token vuelve a su aplicación con `error=access_denied`.
4. **Un cliente público no recibe refresh token**, aunque declare el *grant*. Verificado con dos clientes idénticos salvo el secreto. Por eso no hay renovación silenciosa y el access token dura 2 h.
5. **Un método `@Bean` no puede llamarse `app`**: colisiona con el bean de la clase anotada `@SpringBootApplication`.

- [ ] **Step 3: Implementar el simulador**

Usa `com.sun.net.httpserver.HttpServer`, que viene en el JDK: **no añadas una dependencia de WireMock para esto**.
